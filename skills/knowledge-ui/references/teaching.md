# 教学重构与内容核验

从读者要解决的真实问题出发。列出先决知识、需要迁移的判断和适用范围，再重新组织材料。读者应该能用一段自己的解释或一次小计算证明理解。提取可验证命题，按因果、推导或执行顺序重新写作。只为分析原措辞时保留必要的短引文并注明出处。示例应自行构造或注明数据来源及改编方式。

| 内容类型 | 教学骨架 | 验证重点 |
|---|---|---|
| 概念 | 问题与动机、定义、相近概念、适用场景 | 典型正例和一个可说明边界的反例 |
| 原理 | 关键部件、因果链、状态变化、失效条件 | 同一输入下一步为何发生，改变假设会怎样 |
| 数学与工程 | 假设、公式来历、符号、关键推导、直觉、局限 | 量纲、适用域、分段衔接、独立复算 |
| 计算机系统 | 分层、控制或数据流、对象与生命周期、共享关系 | 文档适用的系统和版本，命令、代码及可观察结果是否一致 |
| 协议与算法 | 问题模型、数据和报文、时间顺序、状态改变、不变量 | 容易遗漏的分支、异常或终止条件，复杂度适用的输入和模型 |

## 事实和公式

1. 给关键事实和外来数据保留可追溯出处，优先使用标准、原始研究、项目维护文档或器件数据表。给出定位所需的版本、章节或表号。区分原文事实、作者推导、示例设定和待确认说法。原始资料有出入时，把分歧和适用条件写清楚。
2. 先列变量、单位、有无量纲、参考方向或初始条件。交代每一步来自定义、守恒、模型假设或近似。定量比较注明单位转换、精度和舍入规则。
3. 用一种独立于 YAML 实现的方式复算。例如手算输入输出、用单独的测试向量求值或核对可信参考数据。至少选默认输入及有教学价值的边界，按模型补充零点、极限、分段两侧或反例。检查图表标签、数据、公式和练习答案彼此一致。
4. 让核心知识脱离围栏仍可读。正文解释图在回答什么以及至少一个可核对的输入输出或状态序列。自测题让读者预测结果或解释错误选项，反馈指出相应机制。根据论点和学习任务安排每节结构。

结构、运行表现和知识核验各有直接证据。静态校验复用生产 CLI。交互在 Preview 或实际宿主检查。知识核验记录出处与复算值。交付时说明每项实际验证的范围。
